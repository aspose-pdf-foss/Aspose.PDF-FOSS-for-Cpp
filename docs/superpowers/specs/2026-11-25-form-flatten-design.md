# Form::Flatten без потери значений — дизайн

Дата: 2026-11-25. Статус: на согласовании.

## Зачем

Цель — полноценная работа пользователя с формами: открыть или создать форму, заполнить,
сохранить и при необходимости «сплющить» (Flatten) в обычное содержимое страницы. Сейчас
`Form::Flatten()` очищает список полей и при сохранении удаляет `/AcroForm`
(`src/public/document.cpp`, ветка `flatten` в `AppendAcroFormUpdate`). Значения на страницу
не попадают — введённые данные пропадают. Это первый шаг; генератор внешнего вида, который
здесь появляется, потом используют `Field::Flatten`, `AddFieldAppearance` и Flatten аннотаций.

## Цели

1. `Form::Flatten()` + `Save()` переносят видимое содержимое каждого виджета формы в
   содержимое его страницы, затем удаляют виджеты из `/Annots` и `/AcroForm` из каталога.
   Работает и для полей, загруженных из файла, и для добавленных в коде.
2. Значения, изменённые в коде, видны после Flatten (для них внешний вид генерируется
   заново).
3. Попутно (та же машинерия): при обычном `Save()` без Flatten у загруженного поля с
   изменённым значением обновляется `/AP`, а не только `/V` — иначе просмотрщик показывает
   старое значение.
4. Состояние «включено» у загруженных флажков берётся из ключей их `/AP /N` (не всегда
   `Yes`), чтобы `/AS` указывал на существующий внешний вид.

## Не цели (этого шага)

- `Field::Flatten()` для одного поля, `AddFieldAppearance`, Flatten аннотаций — следующие шаги.
- Улучшение вида генерируемого текста: учёт `/DA` (шрифт, размер), выравнивание `/Q`,
  многострочность, comb, авто-размер, символы вне Helvetica/WinAnsi. Сохраняем нынешний вид
  генераторов (Helvetica 12, одна строка). Отдельный шаг.
- Чтение перенесённого текста через `TextAbsorber` (он не заходит в Form XObject) — отдельный
  следующий шаг.
- Перегрузка `Form::Flatten(FlattenSettings)`, JavaScript-события, подписи.

## Анти-цели (провал, даже если «работает»)

- Потеря видимого значения хотя бы одного поля при Flatten.
- Изменение внешнего вида нетронутых загруженных полей (их `/AP` переносится как есть).
- Сломанное содержимое страницы: незакрытый `q`/`cm` в исходном потоке не должен сдвигать
  перенесённые виджеты.

## Подходы (выбран A)

- **A. Перенос через XObject (выбран).** Каждый видимый виджет рисуется в странице как
  `q a b c d e f cm /AspFlN Do Q`, его поток `/AP` подключается в `/Resources /XObject`
  страницы. Так делают Acrobat и pdf.js; работает с любыми чужими `/AP` (сжатые потоки,
  свои ресурсы) без разбора их содержимого. Минус — `TextAbsorber` пока не видит такой текст.
- **B. Встраивание операторов в содержимое страницы.** Текст сразу извлекается, но нужно
  переименовывать ресурсы, распаковывать чужие потоки, учитывать `/Matrix`/`/BBox` — хрупко.
- **C. Только новые поля.** Не закрывает цель для загруженных форм.

## Как устроено

### Генератор внешнего вида (новый внутренний модуль)

Лямбды `text_ap`, `list_ap`, `check_ap`, `radio_ap`, `field_chrome`, `circle_path`,
`escape_ap` выносятся из `AppendAcroFormUpdate` в модуль `src/internal/field_appearance.cpp`
(+ `include/internal/field_appearance.hpp`): чистые функции «тип поля + значение + размер →
текст потока и нужный шрифт». Создание объекта XObject (`emit_ap`) остаётся рядом с кодом
сохранения, но становится общим для обычного сохранения и Flatten. Поведение и вид
существующих новых полей не меняются (это рефакторинг, тесты должны остаться зелёными).

### Порядок при сохранении с Flatten

`Form::Flatten()` больше не стирает поля сразу: он переводит их в снимок «к сплющиванию» и
ставит флаг (для пользователя форма пуста — `Count() == 0`, как в .NET). При `Save()`
`AppendAcroFormUpdate` сначала делает обычный проход по этому снимку — новые поля
записываются с `/AP` и попадают в `/Annots`, изменённые загруженные получают новый `/AP`, —
затем отдельным инкрементальным проходом переносит все виджеты в содержимое страниц и
удаляет `/AcroForm`. Так Flatten работает по уже согласованному состоянию файла, и
обход `/Annots` видит виджеты новых полей.

### Выбор потока для каждого виджета

Виджеты ищутся обходом `/Annots` каждой страницы (`/Subtype /Widget`), а не по списку
`/Fields`, — так покрываются и поля с отдельными виджетами-детьми (`/Kids`, группы
переключателей).

- Виджет нового поля или поля с изменённым значением → поток генерируется заново.
- Виджет нетронутого загруженного поля с `/AP` → берётся `/AP /N` (если это словарь
  состояний — элемент по `/AS`).
- Загруженное поле без `/AP` (например, файл с `NeedAppearances true`) → генерируется по
  значению.
- Пропускаются: флаги `/F` Hidden (бит 2) и NoView (бит 6); виджет с пустым `/Rect`.

### Размещение (PDF §12.5.5)

Матрица `cm` отображает `/BBox`, преобразованный `/Matrix` потока, в `/Rect` виджета
(масштаб + сдвиг). Для сгенерированных потоков это просто `1 0 0 1 llx lly`.

### Изменение страницы

- Существующее `/Contents` обрамляется: новый поток `q` в начало и `Q` + перенесённые виджеты
  в конец (защита от незакрытого `q`/`cm`).
- `/Resources /XObject` страницы дополняется именами `AspFl1…N` (без конфликта с
  существующими).
- Перенесённые виджеты удаляются из `/Annots`; остальные аннотации страницы остаются.
- `/AcroForm` удаляется из каталога (как сейчас).

### Обычное сохранение (цель 3)

При повторном выпуске изменённого загруженного поля: если у поля есть `/Rect` (поле и
виджет — один объект), к нему пишется новый `/AP`; если есть `/Kids`, новый `/AP` пишется
каждому виджету-ребёнку. Для флажков `/AS` = имя состояния «включено» из `/AP /N` (иначе `Yes`).

## Проверка

TDD, тесты в `tests/forms_flatten_smoke_test.cpp`:
- Новое текстовое поле со значением → Flatten → Save → перечитать: нет `/AcroForm`, нет
  виджетов в `/Annots`, на странице есть `Do`; рендер страницы (`PngDevice`) даёт тёмные
  пиксели внутри `/Rect` поля.
- Загруженная форма (созданная и сохранённая библиотекой), значение изменено → Flatten → рендер
  показывает новое значение (сравнение с рендером до изменения в той же области).
- Нетронутое загруженное поле → его исходный поток `/AP` переиспользован (тот же объект).
- Флажок включён/выключен, переключатель, список — попадают на страницу в нужном состоянии.
- Hidden-виджет не переносится; посторонняя аннотация на странице сохраняется.
- Обычный Save: изменённое значение загруженного поля → у виджета новый `/AP`.
- Существующий тест `FormsLoadOnOpen.FlattenRemovesAcroFormAfterReload` остаётся зелёным.
- Весь набор тестов зелёный.

## Решения, принятые мной (проверьте)

- Модуль генератора — внутренний (`include/internal`), публичный API не меняется.
- Имена ресурсов `AspFl<N>` по аналогии с существующим `AspHelv`.
- Обрамление `q … Q` исходного содержимого всегда, даже если поток сбалансирован.
- Флаг Print (бит 3) не учитывается: переносим всё, что видно на экране, как Acrobat.
- Flatten = обычное сохранение формы + отдельный проход переноса (см. «Порядок при
  сохранении»); после `Flatten()` форма для пользователя пуста.
- Генерируемый вид для изменённых загруженных полей — тот же, что у новых полей (рамка,
  Helvetica 12), а не стиль исходного файла; учёт `/DA` — следующий шаг.
